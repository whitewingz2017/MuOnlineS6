# Mobile player panel

The mobile top-left panel is implemented by `Client.Main/Controls/UI/Game/Hud/MobilePlayerPanel.cs` and added by GameScene. Desktop HUD visibility is unchanged.

It displays the character's actual loaded head/mask and armor models, name and level, live HP/MP/SD/AG current/maximum values with thousands separators, and a Normal/PK targeting toggle. The portrait uses a cached 160x160 render target, refreshed four times a second, and is clipped to the circular frame with batched sprite strips. It uses idle model geometry and current equipment rather than a fixed class illustration. It does not change the world character or camera.

The four bars follow the supplied sample: red HP, blue MP, purple SD, green AG. The source fill files named AG and SD have those opposite sample colors, so the UI maps them accordingly. Empty and zero-maximum bars are clamped safely. Names shrink to fit the top plate. Layout uses virtual window bounds and scales down on narrow layouts. Buff icons move below the new panel.

Normal preserves ordinary monster targeting and existing duels. PK permits selecting other live players outside safe zones through the same manual/held-skill target callback. Both participants' terrain flags are checked. The server still decides whether an attack is valid. No live tablet combat test has been performed for this new button.

Assets are copied into `Client.Main/Data/MobileHud` and embedded in the shared client assembly, so they do not depend on a patch being uploaded separately. Frames/buttons come from `data/patch/files-e.g/Interface/NEW_HUD`; colored fills come from the user's `C:/MuOnline_Source/MuMobileHUD_Separated_PNG` reference asset folder. The panel owns and disposes its textures and portrait render resources.

Validation: WindowsDX client/fixture and OpenGL desktop builds; offline production renders for equipped Dark Knight, Fairy Elf and Summoner portraits; Normal/PK appearances; depleted HP and zero-maximum MP. The fixture uses synthetic display stats and does not connect to or change the user's server character. Final face-framed preview is `Publish/MobilePanelFacePreview/skill-0-frame-064.png`. Android APK build/install intentionally not performed.

To reproduce the offline panel preview, build tests/SkillRenderCapture and set TWINMU_MOBILE_PANEL_CAPTURE=1. The fixture switches the display mode at frame48 and exercises empty resources between frames24 and48. TWINMU_ITEM_CAPTURE_MATCH=1 equips the recorded Dragon Knight set for a gear portrait check.

Theme and targeting update: Windows Debug shows this panel only when Classic Phone is selected; Windows Release keeps phone preview unavailable. A fresh Windows profile defaults to Classic PC (the bundled settings no longer force Hybrid). Hybrid remains an explicit settings choice. Mobile mode overrides the desktop HUD shell while active. Desktop Ctrl enables player targeting and the attack cursor; mobile PK includes nearby players and retains a tapped player as the focused attack/skill target. Normal clears player focus and active attacks. Safe-zone checks apply to both participants. The mobile player menu does not consume PK attack taps. Offline Debug and Release interface-default checks passed; live PvP has not been verified.

PNG overrides: in Debug, the panel looks up the source tree from the executable directory and uses the newest matching PNG from Client.Main/Data/MobileHud or data/patch/files-e.g/Interface/NEW_HUD. Installed builds first use Data/Interface/NEW_HUD, then embedded fallback images. Textures load once per panel lifetime; restart after editing. Verified char_profile, bar_empty_1 and nameplate_top embedded hashes in the new debug build match the edited source files; the previous normal debug output still contained older images.

Layout update: nameplate moved closer to the portrait; name and level have individual bounds within its two boxes. Existing helper settings/start-stop icons and hit areas move beside the level in Mobile theme; desktop layouts retain their placement. Mobile resource order is HP, MP, AG, SD, with buffs anchored directly below SD. Normal/PK opens a two-choice menu; choosing the current mode does not toggle it. Offline input checks passed for opening, PK selection, repeated PK selection, and returning to Normal; rendered preview: Publish/MobileHudModeListPreview/skill-0-frame-064.png. Windows Debug fixture build passed; no APK built.
